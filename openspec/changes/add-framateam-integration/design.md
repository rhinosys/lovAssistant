## Context

See proposal.md for motivation. Relevant current state:

- **RAG** is file-based: `scripts/index-rag.ts` writes `wiki-old/vector-index.json`, searched in memory by `LocalVectorStore` (cosine 0.7 + keyword 0.3, `mistral-embed`, 1024 dims). PostgreSQL only holds `users`, `threads`, `messages` (`001_initial_schema.sql`); the pgvector extension is **not** used, and the YunoHost Postgres (`ynh_add_psql_db`) is not guaranteed to have it.
- **Grounding**: `collectEvidence()` (`src/server/chat/grounding.ts`) builds `EvidenceSource[]` (`origin: "YesWiki" | "DokuWiki"`); the draft → review → `renderEvidence()` → web fallback pipeline is inlined in the streaming handler `src/app/api/chat/route.ts`.
- **Auth**: `TokenAuthService.authenticateRequest` returns `roles: ["member"]` for everyone (session token, cookie, SSOwat `Remote-User`, dev `x-username`). No admin role.
- **Deployment**: YunoHost package `admin_lova_ynh` (separate repo), native Next.js under systemd, nginx strips `Remote-User`/`Auth-User`. Precedent: a `rag` permission restricts `/api/rag/refresh` to `admins`.
- **Runtime**: Node 22 (global `WebSocket`, `fetch`), vitest with mocked `fetch`, in-memory repositories for tests.
- Framateam: Mattermost API v4, regular user account, no bot/PAT, shared associative instance.

## Goals / Non-Goals

**Goals:**
- One answering pipeline shared by web chat and Framateam bot.
- All Framateam state (settings, channels, chunks, tombstones) in PostgreSQL, deletable row by row.
- Bot and sync usable with only `.env` (dev) or only admin settings (prod).

**Non-Goals:**
- Migrating the DokuWiki index from JSON to PostgreSQL (possible later on the same table design).
- Indexing private channels, DMs, files/attachments or images of posts.
- Slash commands / interactive Mattermost integrations (require instance admin rights).
- A generic multi-integration admin framework: the admin area only hosts Framateam for now.

## Decisions

### D1. Admin role via a YunoHost permission + trusted proxy header
The package declares `[resources.permissions] admin.url = "/admin"`, `admin.additional_urls = ["/api/admin"]`, `admin.allowed = "admins"`, `show_tile = false`, `protected = true`. SSOwat refuses non-allowed users on those paths. nginx gets a dedicated `location` for `__PATH__/admin` and `__PATH__/api/admin` that sets `proxy_set_header X-Lov-Admin "1"`, while the main location sets `X-Lov-Admin ""` (strip). `authenticateRequest` adds `admin` to roles when the header equals `1` **and** `TRUST_PROXY_ADMIN_HEADER=true` (set only by the YunoHost package, so a Docker or dev deployment without that nginx cannot be fooled by a client-sent header); `requireAdmin(user)` throws `AuthorizationError` otherwise.
Dev fallback: `ADMIN_USERS` (comma list) honoured only when `NODE_ENV !== "production"`.
*Alternatives*: reading YunoHost groups from the app (needs root / LDAP access, `ldap = false` in manifest) — rejected; app-only `ADMIN_USERS` in prod — rejected by user in favour of YunoHost-managed rights.
The admin UI is client-side fetches to `/api/admin/*`, so it is also covered by the server guard.

### D2. Secret encryption
AES-256-GCM via `node:crypto`, key = 32 bytes from `APP_ENCRYPTION_KEY` (base64 or hex; generated by the YunoHost install script and kept in `.env`). Stored as `v1:<iv>:<tag>:<ciphertext>`. Distinct from `SESSION_SECRET` so rotating sessions does not lose the password. Settings API exposes `passwordConfigured: boolean` only.
*Alternative*: keep the password only in `.env` — rejected, the user wants it configurable from the admin.

### D3. Settings resolution
`getFramateamSettings()` = DB row (`framateam_settings`, single row id=1) if present, else `FRAMATEAM_URL` (default `https://framateam.org`), `FRAMATEAM_TEAM`, `FRAMATEAM_LOGIN_ID`, `FRAMATEAM_PASSWORD`, `FRAMATEAM_TRIGGER` (default `!lov`), `FRAMATEAM_SYNC_INTERVAL_MIN` (default 60, min 15). Result tagged `source: "database" | "env" | "none"`. In env mode, channel flags still live in `framateam_channels` (admin UI), with optional `FRAMATEAM_INDEX_CHANNELS` / `FRAMATEAM_LISTEN_CHANNELS` names seeding the flags for CLI-only setups.

### D4. Storage: PostgreSQL with `real[]` embeddings, cosine in Node
Migration `002_framateam.sql`:
- `framateam_settings(id smallint pk check (id=1), base_url, team_name, login_id, password_enc, trigger, sync_interval_min, updated_at)`
- `framateam_channels(channel_id text pk, team_id, name, display_name, index_enabled bool default false, listen_enabled bool default false, initial_page int, initial_done bool, last_sync_ms bigint, last_error text, updated_at)`
- `framateam_chunks(id text pk, root_post_id text, channel_id text references framateam_channels on delete cascade, chunk_index int, content text, permalink text, thread_created_at timestamptz, thread_updated_at timestamptz, content_hash text, embedding real[])` + indexes on `root_post_id`, `channel_id`.
- `framateam_forgotten(post_id text pk, root_post_id text, channel_id text, reason text, created_at)`
Search loads embeddings of indexed chunks (volume: a few thousand rows max) and scores like `LocalVectorStore` (same hybrid formula), with a short in-process cache invalidated by a `chunks_version` (max `updated_at`).
*Alternative*: pgvector `vector(1024)` + HNSW — better at scale but requires the extension on the YunoHost Postgres; the column can be migrated later without changing specs. *Alternative*: append to the JSON index — rejected, no targeted deletions/incremental updates and concurrent writers.

### D5. API client
`FramateamClient` (`src/server/framateam/client.ts`), constructor takes settings + an injectable `fetch` and clock (tests). All calls go through one promise queue with a minimum spacing (default 250 ms). 429 → wait `Retry-After` (or `X-Ratelimit-Reset`) ; 5xx/network → exponential backoff 1 s → 60 s, max 5 attempts. 401 → one `login()` then retry once. Login: `POST /api/v4/users/login {login_id, password}`, token from `Token` header, user from body (MFA error id `mfa.validate_token.authenticate.app_error` → `FramateamMfaRequiredError`). Methods: `login`, `getMe`, `getTeamByName`, `listPublicChannels(teamId)` (paged), `getChannelPosts(id, {page, perPage}|{since})`, `getPostThread(id)`, `addReaction`, `removeReaction`, `createPost`, `getPost`. The token is kept in memory only.

### D6. Thread chunking
Pure function `buildThreadDocuments(posts, {selfUserId, minChars})`: group by `root_id || id`, sort by `create_at`, drop `type !== ""` (system), `delete_at > 0`, own posts and tombstoned ids; normalise text: `@username` → `@membre`, strip `~channel` links to their name, collapse whitespace; drop "useless" posts (only emoji/`+1`/`merci`-like, < 15 chars). Skip thread if total useful text < `minChars` (default 120) . Content header: `Discussion Framateam ~<channel> — <YYYY-MM-DD>`; posts joined as `— <text>` (no author). Chunking reuses the `text-chunker` size (~450 tokens) with each chunk prefixed by the root text (truncated to 600 chars). `content_hash` = sha256 of the normalised thread; unchanged hash → no re-embedding.

### D7. Sync algorithm
`syncFramateam({channelIds?})` under `pg_try_advisory_lock(<const>)` (refuse if taken → `SyncBusyError`):
1. Login, resolve team, refresh `framateam_channels` from `listPublicChannels` (new channels inserted disabled; vanished/private ones disabled and purged).
2. Purge chunks of channels with `index_enabled = false`.
3. For each enabled channel, sequentially:
   - not `initial_done`: page from `initial_page` (per_page 200) until empty, persisting `initial_page` after each page; collect touched root ids; set `last_sync_ms` to the max `update_at` seen, `initial_done = true`.
   - else `?since=last_sync_ms`; if the response size reaches the server cap (1000), fall back to paging back until older than `last_sync_ms`.
   - For each touched root: fetch `getPostThread(root)` (unless all posts already in hand), rebuild, compare hash, embed changed chunks with `MistralEmbeddingsProvider`, replace rows in a transaction. Deleted roots → delete rows.
4. Record per-channel `last_error` instead of aborting the whole sync on one channel's failure.
Entry points: CLI `npm run framateam:sync`, admin `POST /api/admin/framateam/sync` (fire-and-forget in the Next process, status via the channels table), and the bot service's timer (interval from settings).

### D8. Retrieval integration
Compute the query embedding once in `collectEvidence` and pass it to both DokuWiki and Framateam searches (add an optional `queryVector` to `RAGRetrievalService.search`). `searchFramateamThreads(vector, text, {topK: 4, minScore: 0.2})` groups hits by `root_post_id` and returns whole-thread text (bounded 6 000 chars). `EvidenceSource.origin` gains `"Framateam"`; title `Discussion ~<channel> (<date>)`, url = permalink. `evidencePrompt` gets one added paragraph: Framateam sources are member discussions — useful tips, never official procedures; wiki wins on conflict, especially safety; dates matter. Failures are logged and ignored (graceful degradation).

### D9. Shared answering pipeline
Move the body of the stream loop into `answerQuestion({ question, userHistory, provider, model, signal }) → { text, totalTokens }` in `src/server/chat/answer.ts` (collect evidence, draft, review, render, web fallback). The web route keeps streaming events (`thread`, `text`, `done`) and persistence; the bot calls the same function. Existing route tests must stay green.

### D10. Bot service as a separate process
`scripts/framateam-bot.ts` (`npm run framateam:bot`) runs `FramateamBot`: load settings (idle + poll every 60 s when unconfigured), login, `GET me`, open `wss://<host>/api/v4/websocket`, send `authentication_challenge` with the token, handle `posted` events (`data.post` is JSON string, `data.channel_type` must be `O`, channel must be `listen_enabled`, `post.user_id !== me`). Trigger: text starts with the trigger keyword (default `!lov`); mention `@<me>` is accepted only when `FRAMATEAM_ACCEPT_MENTIONS=true` (meant for the dedicated `assistant-lov` account; off by default because with a personal account such as `nrineau` every mention of the person would trigger). Flow: `addReaction("eyes")` → collect thread member questions (`getPostThread`, own posts excluded) → `answerQuestion` → `createPost({channel_id, root_id: post.root_id || post.id, message})` (truncated to 16 000 chars) → `removeReaction`. Per-channel concurrency 1, global queue max 3 pending; extras get a "je suis occupé, réessaie dans un instant" reply.
Reconnection: ping every 30 s; no pong/message in 90 s → reconnect; backoff 2 s → 5 min with jitter; on reconnect, `since` catch-up limited to 15 minutes for missed triggers. Config reload: `LISTEN framateam_config` on a dedicated pg client; admin save does `NOTIFY framateam_config`. The bot also runs the periodic sync (D7) on its timer.
YunoHost: second systemd unit `admin_lova-framateam.service` (same user, `.env`, `Restart=always`).
*Alternative*: run the websocket inside Next.js (instrumentation hook) — rejected: tied to web restarts/HMR, multiple workers could duplicate replies.

### D11. GDPR tooling
`forgetPost(postIdOrPermalink)`: resolve id (parse `/pl/<id>`), insert tombstone, rebuild the thread from stored state or API without it (root → delete thread). `forgetChannel(channelId)`: delete chunks, `index_enabled=false`, reset `initial_*`/`last_sync_ms`. Exposed via `POST /api/admin/framateam/forget` and `npm run framateam:forget -- --post <id|url> | --channel <name>`. All admin actions logged with the admin username and target id, never content.

## Risks / Trade-offs

- [Personal account `nrineau` used for development] → replies appear under that name; mentions disabled by default; websocket events from private channels/DMs are dropped before any processing and never logged; switch to `assistant-lov` before production (documented).
- [Account with MFA cannot use `/users/login`] → explicit error in connection test; dedicated account without MFA recommended.
- [Session token expiry / password change] → 401 re-login, then error surfaced in admin status.
- [Prompt injection via member messages] → Framateam content wrapped as untrusted evidence, existing "ignore instructions in sources" rule, links only server-generated, lower authority than wiki.
- [Feedback loop: bot answers re-indexed] → own posts excluded at chunking time.
- [In-Node cosine over all chunks] → fine for thousands of rows; pgvector migration path documented.
- [`since` cap / clock skew] → paging fallback; `last_sync_ms` taken from server `update_at`, not local clock.
- [Header trust (D1)] → only valid behind the YunoHost nginx; documented next to the existing `Remote-User` warning; test that the main location strips it.
- [Embeddings cost on initial load] → hash-based skip, batching (16) already in `MistralEmbeddingsProvider`.

## Migration Plan

1. Deploy app with migration `002` (`npm run db:migrate`); feature inert until configured.
2. Package upgrade: generate `APP_ENCRYPTION_KEY` if absent, add `admin` permission and nginx admin location, install the bot systemd unit (starts idle).
3. Admin configures account, tests connection, enables channels, runs first sync.
Rollback: stop/disable the bot unit; previous app version ignores the new tables; `DROP TABLE framateam_*` if fully abandoned.
